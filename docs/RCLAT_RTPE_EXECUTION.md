## Frozen behaviour enforced by the runner

The runner loads training and validation windows from the same bound common-origin inventory. It fits a fresh weighted training-input-only scaler and applies it to both arms and target horizons. No old P10 scaler is reused. Ridge fits all six registered alphas in order using the CPUfloat64 weighted solver, checks residuals, scores only validation data and saves every candidate with its validation per-origin losses.

The fresh seed17 pooled-multiscale GRU uses hidden64, scales1/4/16 and the frozen three forecast heads. The unused order readout remains in saved state for model compatibility but has gradients disabled and is excluded from AdamW. No linguistic or behavioural supervision is active. The CPU generator seeded2026102301 draws128 uniform global origin indices with replacement on each of5,000updates. Loss is N/B times the batch weighted sum; there is no batch-local weight normalisation.

Every update checks finite forecasts, loss, active gradients before clipping, clip norm, parameters and optimiser state. Walltime and peak host RSS are checked throughout fitting and evaluation. Per-step logs retain exact global indices, loss, LR, gradient norm, elapsed time and peak host RSS, with a separately saved index-to-recording/origin table. Failure records retain phase, step and exact current indices.

Every250updates, validation primary80ms loss is recorded and a checkpoint saves model, optimiser, CPU/sampler/XPU RNG state, step and provenance hashes. Every checkpoint and Ridge candidate receives a SHA256. All5,000updates, all20validation points and all six Ridge candidate scores must exist before selection can lock. Exact ties follow the frozen order: earliest listed alpha and earliest GRU step. A favourable intermediate score never stops training.

Only after selection.json is written and every checkpoint hash is checked does the production path call the internal-evaluation loader. Before then the core refuses evaluation loading without a selection lock. The production selection is generated by the complete-budget ledger, not by user-supplied scores or checkpoints. Sources are checked for integrity during preparation; this is distinct from computing held-out predictive scores.

Evaluation computes observed-cell loss within each origin/horizon, equal-origin recording means, equal-recording speaker means and equal speaker macro means. It retains normalised future-feature forecasts, masks, targets, identities and per-origin errors for selected Ridge, selected GRU and final GRU. The paired speaker bootstrap and strict positive-point/positive-lower-bound decision come from the frozen helper. Secondary horizons and final-checkpoint results never replace the selected-model primary80ms endpoint.

Dependency integrity is checked before each Ridge candidate, at GRU checkpoints, before evaluation unlock and before final results. The2hwalltime,8GiBhostRSS and Ridge residual limit remain unchanged. Incomplete execution preserves artifacts and leaves the gate unevaluated. No repair, retry, resumption, precision/batch/LR/capacity change or budget extension occurs.
